# Tappa 1 · Fondamenta — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** un monorepo con confini verificati, configurazione, log, database, coda, web e worker avviabili, design system con tema chiaro/scuro, immagine Docker irrobustita, `install.sh`/`update.sh` e CI completa: installabile sulla VPS con un comando.

**Architecture:** pnpm workspace con `apps/web` (Nuxt 4), `apps/worker` (Node) e i pacchetti `domain`, `application`, `infrastructure`, `config`, `contracts`, `ui`. Una sola immagine con i comandi `web`, `worker`, `migrate`, `cli`. Postgres con due ruoli (migrazioni e applicazione), pg-boss nello stesso database.

**Tech Stack:** Node 24 LTS, pnpm (ultima major, fissata con `packageManager`), Turborepo 2, TypeScript 6.0, Nuxt 4 + Nuxt UI 4, PostgreSQL 17, Drizzle ORM + drizzle-kit con driver `pg`, pg-boss 12, Zod 4, pino 10, Luxon, uuid (v7), Vitest, Testcontainers, Playwright + @axe-core/playwright, dependency-cruiser, ESLint 10 (`@nuxt/eslint`), Prettier, Husky, commitlint, release-please, Renovate, shellcheck, bats-core.

**Spec:** `docs/superpowers/specs/2026-10-15-feedway-design.md` (§5 RNF-08/09, §6, §7, §14.3, §15.3, §15.5, §15.6, §16.2–16.3, §16.5–16.7, §17). Piano quadro: `docs/superpowers/plans/2026-10-15-00-piano-generale.md`.

## Global Constraints

- Node `>=24.11 <25`; `.nvmrc` = `24`. TypeScript `~6.0.3` con `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`. Nessun `any` senza commento `// eslint-disable-next-line … -- motivo`.
- Moduli ESM ovunque (`"type": "module"`).
- Pacchetti con scope neutro `@app/*`; nome visibile solo da `PRODUCT_NAME` in `packages/config/src/product.ts` (piano generale §3).
- `domain` non importa nulla al di fuori di sé stesso; `application` importa solo `domain` e `zod`; `infrastructure` implementa le porte di `application`; `apps/*` compongono. Nessun pacchetto importa da `apps/*`.
- Ruoli Postgres: `app_migrator` (proprietario dello schema, usato solo da `migrate`), `app_runtime` (solo DML). Database `app`. Schema della coda `pgboss`.
- Segreti passati come file (`*_FILE`), mai come variabili in chiaro nell'immagine o in `compose.yml`.
- Container applicativi: utente non root (uid 10001), `read_only: true`, `/tmp` in `tmpfs`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, `init: true`, nessuna porta sull'host, healthcheck, `restart: unless-stopped`.
- Limiti risorse (§16.6): postgres 1 GB / 0,5 CPU (`shared_buffers=256MB`), web 768 MB / 0,5, worker 2 GB / 1,0.
- Immagini base fissate per digest (`image@sha256:…`), mai `latest`.
- Header di sicurezza (§15.3): CSP con nonce, HSTS, `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`.
- Errori verso il browser generici con ID richiesta; dettaglio solo nei log.
- Testi dell'interfaccia in italiano. Viste telefono e computer, tema chiaro e scuro, axe senza violazioni.
- Commit in Conventional Commits, un commit per task (più i commit "test:" dei passi rossi se l'esecutore li separa).

## Review Focus

1. **`install.sh` rilanciato su un'installazione esistente** non deve rigenerare password o chiave di cifratura: perderebbe l'accesso al database e ai segreti cifrati. → Task 11, test `install keeps existing secrets on rerun`.
2. **File di segreto con a capo finale o chiave della lunghezza sbagliata** (tipico di `echo` o di un editor): l'a capo va tolto, una chiave che non decodifica a 32 byte va rifiutata con un messaggio che nomina la variabile senza mostrarne il valore. → Task 3.
3. **Postgres che si riavvia mentre web è acceso**: `/api/health` resta 200, `/api/ready` va a 503 e torna 200 da solo senza riavviare web. → Task 8, test `ready recovers after database restart`.
4. **SIGTERM al worker durante un lavoro** (aggiornamento, riavvio VPS): il lavoro non si perde; viene completato entro il timeout o ripreso al riavvio. → Task 7.
5. **Aggiornamento con migrazione fallita**: `update.sh` esce con errore e web e worker della versione precedente restano accesi e sani. → Task 10, scenario `failed migration keeps previous web running` dello smoke test.
